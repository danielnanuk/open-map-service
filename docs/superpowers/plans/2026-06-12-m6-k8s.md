# M6:K8s 部署、横向扩容与数据滚动更新 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 全栈以原生 YAML 部署进 K8s(k3d 全程验证),数据更新走"不可变数据镜像 + 滚动 Deployment",支持横向扩容、零中断滚动与一键回滚。

**Architecture:** 数据即镜像(OSRM×3/Valhalla,kaniko Job 集群内构建)+ Nominatim initContainer/S3 例外;周更 CronJob 编排 ETL→漂移闸→alias 切换→数据镜像构建→patch 滚动→golden 验证→失败 undo;PostGIS/OpenSearch 为 StatefulSet。

**Tech Stack:** k3d(本地验证)· kaniko(无特权构建)· MinIO(k3d 期 S3 替身)· 原生 YAML + EDIT-ME 注释块

**Spec:** `docs/superpowers/specs/2026-06-12-k8s-deployment-design.md`(验收表 §9,假设 §10)。

**执行纪律(M1-M5 经验 + 本里程碑特有):**
- 前台执行 + 充足 timeout;长构建用 `kubectl wait/logs -f` 轮询
- **资源现实**:开发机 ~8GB RAM / ~14GB 空闲盘——**起 k3d 前必须 `docker compose stop`(保留卷)**,T8 验收完成后恢复;每个任务开头 `df -h /` 检查,<5GB 即先清理(`docker builder prune`)
- 镜像引用一律走 k3d registry(EDIT-ME 注明真集群替换点);manifests 改动后 `kubectl apply -f` 幂等重放验证
- 任何 kubectl 删除/重启操作前确认目标在 `places` namespace 内
